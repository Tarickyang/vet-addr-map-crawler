# 專案案例：從客戶名單到拜訪行程

## 問題與目標

業務只有一份院所名單，難以快速判斷位置分布、同一天應拜訪哪些院所及如何減少繞路。目標是將資料核對、地理位置、業務限制與出訪順序整合成可執行工作流程。

## 本 repository 可執行的功能

- 本機 Web UI：設定縣市、出發點、交通方式與兩個資料來源。
- CSV／JSON／HTML 表格來源整合；臺北來源有專用 adapter，其他來源需設定欄位映射與完整性確認。
- 主來源優先、保守跨來源比對、差異紀錄與待確認清單。
- 保存人工生日、備注、業務限制、固定識別碼與地圖編號。
- 座標人工確認、行政區界匯入；容量平衡分組與有向道路矩陣的組內最短開放順序。
- 每組目標8家、可跨區、不返程；以一致底色輸出分區工作簿、編號地圖及PDF。
- 通用Google Maps地點連結、前後各最多4站的機車導航。
- Windows WSL安裝／啟動腳本、更新腳本與排程設定範例。

## AI的角色與人工責任

AI用於需求拆解、程式撰寫、資料處理與驗證輔助。執行產品不需LLM API key；不會讓模型猜測負責人、座標或缺值。來源優先、人工規則與道路限制需要明確檢查。履歷應依實際參與範圍描述需求、實作、測試及協作貢獻。

## FAB

- 功能：整合來源、視覺化院所位置、規劃每日出訪。
- 優勢：將資料與真實業務限制連接，保留可追溯的來源與核對紀錄。
- 利益：協助業務降低查找位置與安排順序的準備負擔；效益方向明確，尚待實際工時與路程數據量測。

## 已知界線

先分組再求組內最短，不保證全市全域最優。道路名稱掃描不等於完整白牌通行認證，依現場標誌為準。沒有Google Sheets同步、沒有已替使用者安裝的排程、沒有全臺各網站的自動解析保證。詳見README與VALIDATION.md。
